# 02: MCP endpoint + `get_status` (tracer bullet)

**What to build:** When the game starts, an MCP server listens on `http://127.0.0.1:<port>/mcp` (Streamable HTTP, POST-only, stateless). An AI client (e.g. MCP Inspector) can connect, list tools, and call `get_status`, which reports the live game state. This establishes the whole chain: transport → JSON-RPC dispatcher → tool registry → source interfaces → main-thread access, plus the endpoint test harness with fake sources. See spec sections "Module layout", "Lifecycle", "Tools".

## Comments

- Layout: everything under `com.yshs.questmcp.core` is plain Java plus Gson, SLF4J, JSpecify and `com.sun.net.httpserver`. `core.mcp` holds the transport (`McpHttpServer`) and the JSON-RPC dispatcher. `core.tool` holds `Tool`, `ToolRegistry`, `ToolException`, `GameThread` and `GetStatusTool`. `core.source` holds `GameSource`, `GameStatus` and `GameState`. `core.QuestMcpServer` is the wiring that both the mod and the tests start. Game-side code lives in `com.yshs.questmcp.client`: `QuestMcpConfig`, `McpServerLifecycle`, `ClientGameSource` and `QuestMcpJeiPlugin`. A grep of `core` finds no `net.minecraft` / `net.neoforged` / `com.mojang` / `dev.ftb` / `mezz` imports. The test classpath has no Minecraft on it at all; Gson and slf4j-api are added there as test dependencies, at the versions Minecraft 26.1.2 ships.
- Adding a tool: implement `Tool` (name, description, schema, `call` returning Markdown; throw `ToolException` for an `isError` result; read the game only via `GameThread.read`), then add it to the list in `QuestMcpServer.start`.
- Real readiness for `get_status`: in-world means `Minecraft.level` and `player` are set. Quests come from FTB's public `ClientQuestFile.exists()`. JEI comes from a minimal `@JeiPlugin` that keeps the `IJeiRuntime` between `onRuntimeAvailable` and `onRuntimeUnavailable`, so 09 can use that runtime directly. `revealHiddenQuests` is printed as a hard-coded `false` until 05 adds the config option.
- Protocol: the supported versions are `2025-03-26`, `2025-06-18` and `2025-11-25`, the handshake-based Streamable HTTP revisions; the newest is `2025-11-25`. MCP `2026-07-28` (handshake-less, with `server/discover`) is not supported. A request whose `MCP-Protocol-Version` header names an unsupported version gets HTTP 400 with a JSON-RPC error. 2025-06-18+ requires this, and it also makes newer dual-era clients fall back to `initialize`. JSON-RPC batches (arrays) are rejected with `-32600`.
- Done early because the dispatcher needs them anyway; 03 still owns their tests and refinement: non-POST → 405 (one test), `-32700`/`-32600` with HTTP 400, `-32601`, `-32602` for an unknown tool or non-object `arguments`, and unexpected tool exceptions → `isError`. Not done, left for 03: Origin check, bearer token, 404 for other paths (the JDK server matches `/mcp` as a prefix), per-tool schema validation, and a readable "port in use" status (today a bind failure is only logged at ERROR).
- Verified: `./gradlew build` passes, with 23 tests in `McpProtocolTest`, `GetStatusTest` and `ModMetadataTest`. `runClient` under xvfb logged `Quest MCP server listening on http://127.0.0.1:25599/mcp` and created `config/questmcp-client.toml` (`port = 25599`, range 1024–65535). With curl I sent initialize (echoed `2025-06-18`), `notifications/initialized` (got 202 with an empty body), `tools/list`, `tools/call get_status` and `ping`. `get_status` returned `NOT_IN_WORLD` on the title screen, `READY` after "Create Test World" and `NOT_IN_WORLD` again after "Save and Quit to Title", and the server stayed up throughout. After "Quit Game" the JVM exited and port 25599 was free. MCP Inspector was verified through its CLI only (`pnpm dlx @modelcontextprotocol/inspector --cli http://127.0.0.1:25599/mcp --transport http --method tools/list` and `--method tools/call --tool-name get_status`, inspector 2.10.1), not its web UI. It worked in the main menu and in a world: it negotiated `2025-11-25`, and its `GET` for an SSE stream got 405 and was handled gracefully. The intermediate states `QUESTS_NOT_LOADED` and `JEI_NOT_READY` were covered only by the tests; in the real game the change to `READY` took about a second.
