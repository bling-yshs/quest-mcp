# 06: `get_quest` + rich text → Markdown

**What to build:** An AI agent can read a single quest in full — description, tasks with the player's progress, rewards, prerequisites and follow-ups — as clean Markdown it can follow links from. See spec "Rich text → Markdown rules" and "Tools".

**Blocked by:** 05

**Status:** done

- [x] Domain model extended: description as a neutral rich-text tree (text, paragraph/line break, quest link, URL link, image); tasks (type, title, referenced item/fluid IDs with counts, progress); rewards (type, title, item IDs with counts)
- [x] FTB Quests adapter converts quest text components into the neutral tree, discarding styles/colours/formatting codes
- [x] `get_quest(quest_id, lang?)` renders title, subtitle, status, Markdown description, tasks with progress, rewards, prerequisites and follow-ups (with IDs in backticks)
- [x] Quest link → `[<target title>](quest:<id>)`; URL → `[text](url)`; image → `[image: <path>]`; paragraphs separated by blank lines
- [x] With `revealHiddenQuests = false`: hidden quest → "not found" `isError`; hidden prerequisites/follow-ups omitted; links to hidden quests rendered as plain text
- [x] Endpoint tests with a fake `QuestSource` covering every rendering rule, hidden handling, task progress, language fallback
- [x] Manual: sample quest with links, an image, colour codes, item tasks and rewards, verified via MCP Inspector

## Comments

- Model additions (`core.source`, no Minecraft types):
  - `RichText(List<Paragraph>)`; `Paragraph(List<Inline>)`; `Inline` is `Text`, `LineBreak`, `QuestLink(questId, text)`, `UrlLink(url, text)` or `Image(path)`. `RichText.builder()` keeps the tree tidy: an empty or blank line ends the paragraph, no empty paragraphs, no leading/trailing line breaks, adjacent text and adjacent pieces of the same link are merged, `\n` inside text is a line break.
  - `QuestBook.Quest` gained `description` (`Localized<RichText>`), `detailsHidden`, `descriptionHidden`, `tasks`, `rewards`.
  - `QuestBook.Task(type, title, items, progress, maxProgress, completed, visible)`, `QuestBook.Reward(type, title, items, visible)`, `QuestBook.ItemRef(kind, id, name, count)`. `IngredientKind` (`ITEM`/`FLUID`) is top-level so the recipe tickets can reuse it. Type is FTB's type ID (`ftbquests:item`, `ftbquests:checkmark`, `othermod:mana`…), so unknown types still render as type + title.
  - An item task with an item filter (e.g. a tag filter) lists every item it accepts (`getValidDisplayItems`); the Markdown says `8 × any of A, B, C` (at most 10 named, then `and N more`). Item names are the game's display names (game language only).
- `QuestBookView` additions (all hidden filtering stays there, for 07/08): `quests()` (all shown quests in book order), `quest(id)` (same ID normalisation as chapters), `chapter(quest)`, `prerequisites(quest)`, `followUps(quest)` (shown quests whose dependencies contain it, book order), `description(quest)` / `tasks(quest)` / `rewards(quest)` (already reduced to what the book shows unless revealed), `hasUnlistedTasks`, `isDetailsHidden`, `isDescriptionHidden`, `isHidden(Task|Reward)`, `title(Task|Reward)`. 07 should search through `description(quest)`, `tasks(quest)` and `rewards(quest)` so it cannot match text the book hides.
- `get_quest(quest_id, lang?)`: header `# Title (`ID`)`, then `- Subtitle`, `- Status`, `- Chapter: title (`ID`)`, the shared notes, then sections Description, Tasks, Rewards, Prerequisites, Follow-ups (`None.` when empty). Tasks: `- 16x Snowball (`ftbquests:item`): 16 × Snowball (`minecraft:snowball`). Progress: 12/16`, ` (done)` when complete; fluids as `1000 mB × Lava (`minecraft:lava`)`. Prerequisites/follow-ups: `- `ID` Title (STATUS)`, plus `, hidden` when revealed and `, chapter X` when in another chapter. Unknown or hidden ID: `No quest with ID `X` exists. Call get_chapter …` (07 may want to mention search_quests there).
- What the book hides, mirrored from FTB 26.1.2.9 via public API:
  - `hide_details_until_startable` (`quest.hideDetailsUntilStartable() && !team.canStartTasks(quest)`): the book does not open the quest at all (`QuestButton.onClicked`), but the map still shows its title, subtitle tooltip and dependency lines. So `get_quest` shows title, subtitle, status, prerequisites and follow-ups and says the description, tasks and rewards are not known yet. Revealed: everything, with a note.
  - `hide_text_until_complete` (`quest.getHideTextUntilComplete().get(chapter.isHideTextUntilComplete()) && !team.isCompleted(quest)`, `ViewQuestPanel`): the description section says the book shows it only once the quest is completed; subtitle, tasks, rewards stay. Revealed: heading `## Description (hidden in the quest book until the quest is completed)`.
  - Sequential tasks (`getRequireSequentialTasks`): the book lists tasks up to the first incomplete one; so does `get_quest`, with a line that tasks must be done in order. Revealed: all, the unlisted ones marked `(hidden)`.
  - Rewards: the book leaves out `RewardAutoClaim.INVISIBLE` rewards and, when the team's rewards are blocked, blocked ones (`team.isRewardBlocked`). Same here; revealed: marked `(hidden)`.
- FTB rich text (FTB Quests 26.1.2.9 `ViewQuestPanel`, `TextUtils.parseRawText`, FTB Library 26.1.2.9 `TextComponentParser`/`ClientTextComponentUtils`). The adapter (`client.RichTextConverter`) lets FTB parse each line and walks the resulting component tree like `Component.visit`:
  - each description line → a line; an empty line → paragraph break; a line that is exactly `{@pagebreak}` (the book starts a new page) → paragraph break;
  - raw JSON text lines (`[...]`/`{...}` that parse as components) and FTB's own format: `&`/`§` colour and format codes, `&#RRGGBB`, `&z` rainbow, `\n`, `{translation.key}`, `{image:...}`, `{open_url:<url> text:<text with %20>}`. Styles and colours are dropped; leftover `§` codes are stripped;
  - click event `custom` with id `ftbquests:link` and payload `quest_id` (FTB's editor inserts this; `/page` suffix ignored) → quest link. A link to a quest link object leads to its quest; links to other objects (chapters) or unknown IDs stay plain text, as the book cannot open them as quests either;
  - click event `open_url` (raw JSON or `{open_url:...}`) → URL link;
  - `ImageComponent` → image with `imageStr()` (e.g. `minecraft:textures/item/snowball.png`);
  - everything else is plain text: `ftbquests:docs` links, run/suggest command, copy to clipboard, `change_page` (not clickable in 26.1's quest view), hover text (dropped), image click actions. Text FTB fails to parse shows FTB's own error text, as in the book; a line our walk cannot convert falls back to its raw text (caught, logged at debug).
  - Markdown: `[<target title>](quest:<ID>)` in the requested language, or the link's own text if the target may not be shown; `[text](url)` (brackets in the text escaped, URLs with spaces/parentheses in `<…>`); `[image: <path>]`; lines joined by `\n`, paragraphs by a blank line.
  - FTB quirk seen while writing the sample: an `&` code inside `{open_url:... text:...}` ends the substitution early, so the book shows the rest as plain text with an empty link. We show what the book shows.
- Languages: description translations come from `TranslationManager.getEntry(quest, lang, QUEST_DESC)` like the titles; an empty translation falls back to English. Task/reward titles that FTB derives (`16x Snowball`, `XP: +10`) and item names exist only in the game language, so with `lang=en_us` in a Chinese game they stay Chinese (`16x 雪球`); quest titles, subtitles, descriptions and custom task titles follow `lang`.
